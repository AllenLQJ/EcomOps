# 决策记录

| # | 事项 | 裁决 | 理由 |
|---|---|---|---|
| 1 | MinIO 镜像无法拉取（docker.io / quay.io 均失败） | `ObjectStore` 同接口：配置并可达则用 MinIO，否则本地文件；MinIO 后端只有代码，未实测 | 不阻塞合规审查的存储链路；如实披露 |
| 2 | 无真实 LLM | 各"LLM 步骤"用确定性规则，`llm.should_fail(task)` 注入故障验证 `fallback_used` 降级转人工 | 路线图要求降级严禁默认放行，规则实现可被验收 |
| 3 | 三轨/路由规则 | 固化于 `contracts/module_interfaces.md` 第 7 节 | 路线图只给流程图，验收需无歧义规格 |
| 4 | 同一工单并发批准 | PG advisory lock 串行 + 状态判定；相同决定幂等返回，不同决定 409 | 满足"并发点击两次只退一次"，不引入新的对外状态 |
| 5 | 退款回调不在提交请求内同步执行 | 出箱 worker 异步执行（立即触发 + 周期扫描） | EcomPilot 提交 Ops 有 3 秒超时，同步回调会触发其补偿回滚 |
| 6 | 对账顺序 | 先 `GET refunds/status`，SUCCESS 不再 POST | 避免对端不必要的重放；NOT_FOUND 才补发 |
| 7 | 驳回/撤回如何通知 Pilot | 新增 Pilot 内部接口 `POST /internal/v1/aftersales/{claim_no}/result`，Ops 通过 `CLAIM_RESULT` 出箱事件调用；撤回后允许重新申请 | 否则订单永远停在 AFTER_SALE_OPEN |
| 8 | 3C 编号格式 | 16 位数字，格式不符转人工核验 | 实现最初用 14 位，与验收预期及真实编号不符，已修正 |
| 9 | 沙箱演示规则打分 | 命中 ≥2 个关键词视为高置信（≥0.8） | 实现最初对"热水器漏水怎么退换"仅给 0.375，违背"演示规则命中"的预期 |
| 10 | 前端 | Vue 3 CDN 单页，不用 Element Plus / Pinia / 构建 | 本机未装 Node；降为 C 级 |
| 11 | 推送 | 本仓库提交均在本地；是否推送由用户决定 | 仓库公开，长期推送授权仅覆盖 EcomPilot |
| 12 | 接入真实 EcomRAG | 新增 `adapters/ecomrag_adapter.py`（:8002，替代桩）：检索 → EcomRAG `POST /api/v1/chat` 的 `sources`；入库 → 写 md 并调其 `ingest.run --yes`（就地 upsert，文件名决定稳定主键）。不改 EcomRAG 仓库 | EcomRAG 无检索/写入 HTTP 接口，也无租户与类目过滤（这两个参数被忽略）。副作用：每次检索会触发一次 LLM 生成；游客每天仅 5 次配额，联调需调高其 `GUEST_DAILY_LIMIT`；超时放宽为可配置（`ECOMOPS_RAG_*_TIMEOUT_S`） |
