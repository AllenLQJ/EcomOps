| # | 事项 | 裁决 | 理由 |
|---|---|---|---|
| 1 | MinIO 镜像无法拉取（docker.io / quay.io 均失败） | `ObjectStore` 同接口：配置并可达则用 MinIO，否则本地文件；MinIO 后端只有代码，未实测 | 不阻塞合规审查的存储链路；如实披露 |
| 2 | 无真实 LLM | 各"LLM 步骤"用确定性规则，`llm.should_fail(task)` 注入故障验证 `fallback_used` 降级转人工 | 路线图要求降级严禁默认放行，规则实现可被验收 |
| 3 | 三轨/路由规则 | 固化于 `contracts/module_interfaces.md` 第 7 节 | 路线图只给流程图，验收需无歧义规格 |
| 4 | 同一工单并发批准 | PG advisory lock 串行 + 状态判定；相同决定幂等返回，不同决定 409 | 满足"并发点击两次只退一次"，不引入新的对外状态 |
| 5 | 退款回调不在提交请求内同步执行 | 出箱 worker 异步执行（立即触发 + 周期扫描） | EcomPilot 提交 Ops 有 3 秒超时，同步回调会触发其补偿回滚 |
| 6 | 对账顺序 | 先 `GET refunds/status`，SUCCESS 不再 POST | 避免对端不必要的重放；NOT_FOUND 才补发 |
| 7 | 驳回/撤回如何通知 Pilot | 新增 Pilot 内部接口 `POST /internal/v1/aftersales/{claim_no}/result`，Ops 通过 `CLAIM_RESULT` 出箱事件调用；撤回后允许重新申请 | 否则订单永远停在 AFTER_SALE_OPEN |
| 8 | 3C 编号格式 | 16 位数字，格式不符转人工核验 | 实现最初用 14 位，与验收预期及真实编号不符，已修正 |
| 9 | 沙箱演示规则打分 | 命中 ≥2 个关键词视为高置信（≥0.8） | 实现最初对"热水器漏水怎么退换"仅给 0.375，违背"演示规则命中"的预期 |
| 10 | 前端 | Vue 3 CDN 单页，不用 Element Plus / Pinia / 构建 | 本机未装 Node；降为 C 级 |
| 11 | 推送 | 本仓库提交均在本地；是否推送由用户决定 | 仓库公开，长期推送授权仅覆盖 EcomPilot |
| 12 | 接入真实 EcomRAG | 先用适配器（经 `/api/v1/chat` 取 sources、写 md 调 `ingest.run`），后因 EcomRAG 仓库新增原生接口 `POST /api/v1/rag/search` 与 `POST /internal/v1/kb/upsert`（commit 9264677），**适配器已删除**，EcomOps 直接带 `X-Internal-Token`（`ECOMOPS_RAG_INTERNAL_TOKEN`）调用 | 适配器每次检索都触发 LLM 生成、占游客配额、发布要起子进程。原生接口的 score 经余弦校准（远程重排对库外问题也给 ~1.0，不能当置信度）。EcomRAG 仍无租户/类目过滤；超时可配（`ECOMOPS_RAG_*_TIMEOUT_S`） |
| 13 | 买家补证据的 Ops 侧 | 补证据内部接口已存在；新增 `GET /internal/v1/claims/{claim_no}/status` 供 Pilot 查进度（只含状态、轮次、是否需补证据、证据数）。端到端验收 `test_claim_evidence_e2e.py`（真实 Pilot + 真实 Ops）：缺凭证 → 买家补传 → 重审 → 主管批准 → 只退一次，且他人不能代补、重复补返回 409 | 与 Pilot 决策记录第 10 条配套 |
| 14 | 告警控制台 | 告警由 `outbox_events`（FAILED_MANUAL）与卡住的退款回调派生，不另建告警表；人工动作写 `alert_actions`（启动时幂等建表）。重试 = 事件放回 PENDING，由 worker 走既有路径（先查 `refunds/status`，SUCCESS 不再重发），因此不会重复退款；"标记已处理"需填原因。`stuck:` 项只展示不可操作。可选 `ECOMOPS_ALERT_WEBHOOK_URL` 推送新告警，失败静默 | 此前 `CALLBACK_FAILED_MANUAL` 没人知道也没人能处理。"标记已处理"不触碰 Pilot，只表示线下已处理，工单状态保持不变 |
| 15 | 真实 LLM 的使用边界 | 新增 OpenAI 兼容客户端（`ECOMOPS_LLM_BASE_URL/API_KEY/MODEL` 三项都配才启用，默认不联网）。目前只用于证据轨的"是否质量问题"判断：买家文本放进定界符当数据；输出必须是严格 JSON，类型不对即失败；LLM 只能"多提示一个质量问题"，不能抹掉关键词命中，且与规则不一致或自评置信度<0.6 时置信度封顶 0.84，因此**不可能单独触发自动通过**；调用失败/超时/输出不合规走 `fallback_used`。异常信息不带 URL/密钥 | 路线图要求降级严禁默认放行，且买家文本可能含提示注入。仅 mock 测试，未联网实测；Pilot 侧各 agent 仍是确定性模板，未接 LLM |
| 16 | LangGraph 工作流共用地基 | 新增 `core/llm.complete()`（与证据轨共用同一套"三项配置才联网、失败抛 `LlmError`、异常不带 URL/密钥"）、`core/rag.py`（EcomRAG 客户端，失败返回 `None`）、`core/websearch.py`（Tavily → DuckDuckGo，默认 off）；`llm.untrusted()` 把外部文本包进定界标签 | 路线图要求 kb_qa / 合规审查 / 对练也是 LangGraph + AsyncPostgresSaver；这些节点都要调 LLM/RAG/联网搜索，必须有统一的降级与注入防护。联网搜索结果只做兜底回答的参考，不写入知识库 |
| 17 | 售后审核四处补齐 | ① 条款参与三轨（只认明确讲质量问题的句子，防止"7天无理由/非质量问题"缩短质量问题窗口）；② 超时未补材料自动撤回（`ECOMOPS_EVIDENCE_DEADLINE_HOURS`）；③ 驳回/撤回原因随 `CLAIM_RESULT` 回写；④ **修复一个潜在缺陷**：撤回后重新申请会撞上同一个确定性 `claim_no`，旧实现按幂等重放返回已撤回的工单，Pilot 订单会永远卡在 AFTER_SALE_OPEN | 路线图图 3-4 的"超时未补 → WITHDRAWN"和"通知买家驳回原因"此前未实现；④ 是写超时撤回测试时发现的：撤回后重新申请的路径此前没有任何测试走到过 |
| 18 | kb/ask/stream 的错误语义；驳回为终态 | ① 流式问答在响应开始前就跑完整张图，所以越权/不存在是真正的 404、上游失败是 502，不再是"200 + 流内 error 事件"；② 买家进度接口返回审核端的细分状态（`AUTO_REJECTED`/`SUPERVISOR_REJECTED`），Ops 不可用时才退回本地的 `REJECTED`；③ 驳回（自动或主管）是终态，同一订单子项不能再申请（409）；只有撤回/超时撤回才能重新申请 | Codex 原实现把前置错误包进流里；验收（Cursor 依据契约写的）要求 404，复核后采纳验收。驳回终态是保守选择：自动驳回后允许无限重提会被刷，要放开需要另定"补证据后重审"的规则 |
| 19 | 关停时先等后台循环退出 | `lifespan` 里 `task.cancel()` 之后补 `await asyncio.gather(task, return_exceptions=True)`，再关连接池和引擎 | 此前只 cancel 不等待：后台循环若正卡在一次数据库查询里，库先被关掉，它再也拿不到连接，进程（或 TestClient）退出时挂住。以前循环大多数时间在 sleep，没暴露；新增"超时撤回扫描"后循环每轮都查库，测试里稳定复现为整个测试进程卡死 |
| 20 | MinIO 验证方式 | 真实 MinIO 镜像仍拉不下来（Docker Hub 拒绝、quay 401、ghcr denied、bitnami 不存在）。改用 `moto` 的 S3 仿真服务验证 `MinioStore`/`get_store`：上传下载往返、自动建桶、文件名路径穿越被剥掉、同名不覆盖、可达时选 MinIO、不可达时回退本地文件（`tests/unit/test_minio_backend.py`，4 个）。`moto` 只在 `requirements-dev.txt` | 这证明客户端逻辑和 S3 协议交互是对的，**不等于真实 MinIO 服务已实测**；compose 里的 `minio` profile 仍保留，镜像可拉取时即可直接用 |
| 21 | 离线评测与合规检查器的否定语境 | 新增 `scripts/offline_eval.py` + `eval/*.jsonl`（五项，共 147 条自编标注，不具统计意义）。首跑发现合规阻断项检测 precision 仅 52%：大量"不是最好的""不宣称国家级"被判违规；改为否定语境感知（违规词前紧邻否定词才放过，"不骗你，全网最低价"仍算违规）后 precision 92%、recall 仍 100%。剩下一条误判是培训材料里的引用（"'销量第一'属于违规宣传"），规则无法判断，留给 LLM 上下文复核 | 评测集小且是自己写的，数字只说明"这个改动方向对、没有退化"，不代表真实线上表现 |
| 22 | 补齐路线图细节（第三批） | ① 售后图加入 `execute_refund_callback` 节点（防重入登记 + 唤醒 outbox，仍不同步调 Pilot）；② 待审列表按 `priority_boost` 优先排序并带加急标记；③ 合规必填参数表覆盖全部 11 个目录品类，未列出的品类只要求品名 | 对照路线图核出的缺口。① 是图拓扑与路线图对齐，执行语义不变（决策记录第 5 条） |

| 24 | 真流式、问题分类器、截断的流算失败 | ① 配置 LLM 后 `kb/ask/stream`、对练 `chat/stream` 是真正的逐 token 流式（`llm.stream`，LangGraph 自定义事件）；未配置时与旧行为逐字相同。流中途失败时发 `{"reset": true}` 的 token 事件让客户端丢弃已收到的片段，再推降级答案，落库文本等于 reset 之后拼出的文本；越权 session 仍在流开始前 404；客户端断开会取消图任务。② 问题类型：规则判成兜底 VAGUE 时再用训练出来的字符 n-gram 朴素贝叶斯细分（`ECOMOPS_QUERY_CLASSIFIER=on|off`，默认 on）；规则明确判出的类型永远不被覆盖。③ **`llm.stream` 把"既没有 [DONE] 也没有带 finish_reason 的收尾块"的流视为失败**（连接被提前切断） | ③ 是 Cursor 依据契约写的验收用例抓到的：我最初的实现遇到流被切断会当成完整回答，客户端会看到半截答案。分类器的评测集是自编小样本：在专门挑规则答不对的测试集上，"仅规则"26% → "规则+分类器"66%，这个对比有偏（测试集本来就偏向规则的盲区），只说明分类器确实补上了规则的盲区，且在原有 40 条规则评测集上不退化 |
